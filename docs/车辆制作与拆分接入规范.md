# 车辆制作、拆分与 Lua 接入规范

适用范围：现有 16 辆车的外观升级，保留驾驶、座位、联机、比赛传送和回位接口。每车精确值见 [逐车索引](16辆车接口索引.md)。

## 1. 制作单位与尺寸

- 在 Blender 以米为工作单位，应用网格物体的缩放和旋转；导出 GLB。最终 Unity/编辑器坐标以现有样件为对照，不另套未经核验的导入比例。
- **不统一重设 16 辆车的根缩放。** 现有根缩放从 0.6 到 2.0，各车在 `vehicle.json` 中分别记录；新模型须在相同根变换下与现有车宽、车长、座位高度对齐。
- 车辆逻辑沿根局部 `+Z` 前进，根局部 `Y` 为高度。轮胎自转绕脚本 Pivot 的本地 X 轴。GLB 导入可能发生坐标转换，制作时以样件的四轮和车头关系核验，不按名字猜正负方向。
- 使用 `scene-nodes.json` 的父子关系恢复场景。它记录的是编辑器序列化的节点位姿，尤其不能把子节点的 `pos` 直接当作 Blender 局部坐标。

## 2. 拆分规则

| 类型 | 现有接口 | 制作要求 |
|---|---|---|
| 常规四轮赛车 | 车身 + FL/FR/RL/RR 四轮 | 保持逐车 README 的精确节点名；不同车的前缀不能混用 |
| 赤巡摩托 | 车身 + F/R 两轮 | 不补造四轮结构；保留 `FLAME_MOTO_Wheel_F_Part_01` 和 `…_R_…` |
| 宝宝巴、星梦巴 | 逻辑根 + 独立 `LP37_BUSKID_SUNNY_VisualBody` + 四轮 | 逻辑根和可见车身分开；保留六座接口 |
| 暮翼巡游、甜咒南瓜 | 逻辑根 + `Body` + `Wheel_FL/FR/RL/RR` | 隐藏旧载体渲染；只显示独立外观，不能叠出两套车身 |

轮胎几何必须以自身轴心为原点。脚本 `setupWheelVisuals()` 会创建 Pivot、重挂轮胎、把轮胎的局部位置/旋转归零，然后按 `wheelConfigs.radius` 累计自转。若把轮胎原来的整车偏移烘在顶点里，再挂 Pivot 后会偏移或绕大圈。

每辆车的 `README.md` 已直接摘录当前 `seatConfigs` 与 `wheelConfigs`，包括精确的座位名、轮胎挂点、半径和 `visualScale`。原脚本需要的路径若改名或再套一层父节点，`Transform:Find()` 可能找不到，不能只保证 Blender 中“看起来一样”。

如果为了美术增加拆件，优先把装饰放在对应 `Body` 下面，且不要增加独立刚体、交互器或座位。若拆成多个 Renderer，则须同步重建材质匹配配置，不能沿用旧单 Renderer 的材质槽表。

## 3. 两辆节日赛车的明确要求

- **暮翼巡游**：前后串列双座，驾驶前座 `Seat_Driver`，后座 `Seat_Passenger`。当前根缩放 1.749，车身保持低矮赛车比例。
- **甜咒南瓜**：整个主体是一个大南瓜车壳，保持低座舱和前后串列双座；当前根缩放 1.68。现用外观资源是 `C02_FullPumpkinBody_Final`，不能用早期细长车身版本替换。
- 两车后座的交互/网络挂点仍叫 `SeatStation_FrontPassenger`；名字虽然含 FrontPassenger，业务位置是后座，不要为纠正字面含义而改脚本路径。
- `rearLeftTaken/rearRightTaken` 在部分脚本公开变量中保留，是历史字段；**实际座位数以 seatConfigs 为准**，不能由这些字段判断成四座。

## 4. Lua 与场景绑定

| 模块 | 与美术替换的关系 |
|---|---|
| 各车 `pi-*.lua` | 驾驶、刚体/碰撞、交互按钮、座位挂载、轮胎动画、传送/回位协议 |
| `vehicle-seat-station-relay.lua` | 座位交互转发；换外观不能移除既有挂点或改挂到装饰网格 |
| `geocore-material-lifecycle.lua` | 车辆 Awake/Start/OnEnable/OnNetSpawned 时通知材质服务处理当前实例 |
| `geocore-source-materials.lua` | 逐车逐件身份匹配、克隆原生源材质、槽位映射、外观就绪显示与实例缓存 |
| `halloween-vehicle-materials.lua` | 两辆节日车与原有材质服务的衔接 |
| `race-manager.lua` 及 UI/校验模块 | 按既有车名/座位状态执行比赛流程；本次美术升级保留其接口 |

绑定 `scriptId`、节点 ID、参数覆盖值在 `manifests/script-bindings.json` 中。相同 Lua 文件拷贝进目录并不等于编辑器已经挂载；导入后必须在原根节点检查组件绑定。

根节点 ID、车辆名称、脚本 ID、驾驶状态字段、Actor ID、选车名单、16 个固定发车位和比赛回位协议都保留。只换外观不需要更改发车规则，也不需要增加比赛中的补传、赛道检测阻断或全车确认屏障。

## 5. 拓扑或材质槽改变时的必要接入

当前材质配置覆盖 **78 个部件、2011 个材质槽、169 个 palette 条目**。旧 14 车匹配顶点数及子网格数；新两车标记 `strictVertices=false`，但仍匹配名称和子网格数。

制作新拓扑时，依次完成：

1. 按原根比例导入新外观，核对部件命名及座位/轮胎挂点。
2. 采集新 Renderer 的名称、顶点数、子网格数与槽顺序。
3. 为新槽提取实际原生源材质、纹理、关键字和队列，更新服务中的 `palette/fleet` 映射。
4. 更新交付 JSON 和代码中的身份检查，保留“匹配失败不覆盖原材质”的保护。
5. 冷启动、重新出现、联机对象克隆后检查外观；再验证上车、后座、驾驶、发车、结算回位和变身驾驶。

不能为了通过检查而随意关闭所有身份保护，也不能只更新 JSON 不更新真正运行的 Lua。本包 JSON 是可读接口快照；当前服务的运行配置内嵌在 Lua 中。
