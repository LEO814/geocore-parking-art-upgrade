# 停车场资产清单与替换边界

## 范围

采集当前保存场景中停车场高度区域的根对象及全部后代，同时显式纳入停车场围挡子树：**32 个根、731 个节点、74 个独立 GLB**。完整来源和节点关联在 `manifests/assets.json`；节点及组件参数在 `manifests/parking-scene-nodes.json`。这是保存状态快照，不包含用户尚未保存的编辑。

| 组别 | 实际内容 | 升级时的约束 |
|---|---|---|
| 车辆 | 16 车；含 4/2 轮区别、巴士独立可见车身、新车逻辑载体与外观 | 按逐车接口替换，不统一改成五个零件 |
| 母港主体 | `hub-structure-native-optimized` | 保留停车位与可驾驶平面，尺寸/碰撞须与原场景对齐 |
| 节日装饰 | `hub-decor-native-optimized`，含锚点与合并网格 | 保留 `NPC_ANCHOR_N01…N05` 及脚本引用名称 |
| 大型地标 | 南瓜钟塔、蝙蝠新月天文台、糖果锅反应炉；停车区各一处 | 本包按唯一 GLB 去重；赛道上复用同资源的实例不在停车区节点清单内 |
| NPC | 5 个历史命名的载体根、现用视觉模型及骨架 | 场景名称可能保留旧角色名，实际模型以 sourceUri 为准；不要因根名称误换回旧角色 |
| 看板 | 停车场小看板、中文字层、视觉看板、熔脉告示牌 | 保留计时/倒计时脚本绑定及文字表现 |
| 围挡与出生点 | 选车区围挡、舞台外围空气墙、出生点 | 基础方块由编辑器生成，没有独立 GLB；位姿与 Collider 记录在节点清单 |
| 舞台、光效 | 运行时主舞台、光环、聚光灯、NPC 底座与灯带 | 由 Lua 创建，见下文；仅替换静态 GLB 无法完整复原 |

停车场和赛道仍是两块封闭区域。本包不改场地连接，不包含整个赛道/地形工程。

## 运行时生成部分

### 主舞台

`lua/modules/halloween-avatar-service.lua` 的 `H.showBuildStage()` 创建 `Halloween_VictoryStage_Local`。中心：`(168.587784, 52.22828, -29.524362)`；基础台面 `33 × 0.5 × 13`，表演台面 `24 × 0.18 × 10`，包含台阶、冠军小台、音箱、月门光环和 5 个无阴影聚光灯。

这段逻辑还按**世界坐标范围删除旧圆厅的三角面**。更换母港模型或挪动母港时，需要重新核对该范围，否则可能误删新模型的一部分。美术若交付完整舞台，接入人员应有针对性地替换这段视觉生成实现，保留表演触发、相机与回位接口；不能同时显示旧程序舞台和新静态舞台。

`source-reference/` 没有提供“当前舞台最终版”的 Blender 文件，避免把早期提案当最终版。当前准确舞台形状以代码为基线。

### NPC 和灯效

`halloween-avatar-service.lua` 包含程序化骨架、蒙皮/角色外观构建及动作、变身、舞台舞蹈逻辑；`halloween-npc-interaction*.lua` 提供各角色交互；`halloween-hub-fx.lua` 和 `halloween-landmark-lights.lua` 处理停车场与地标灯效。

NPC 的展示尺度与玩家变身尺度分别控制，不要把展示用大模型缩放直接套给玩家。手臂、裙摆权重、坐姿和动作骨骼必须一起验证，避免只提高面数而重新引入开车穿模。

## 文件覆盖与限制

- 74 个 GLB 全部从当前引用 URI 对应缓存提取，文件头与长度通过检查；均无外部文件 URI，资源内嵌情况逐文件列明。
- `source-reference/` 的 6 个 Blender 文件仅为现存可编辑参考，**不保证等于当前导入 GLB**；尤其南瓜车必须以 `C02_FullPumpkinBody_Final` 的现用 GLB 为形状基线。
- 当前代码从保存场景的 `runtimeScripts` 提取。内置 `runtime-resource-root-bootstrap.lua` 与磁盘脚本不完全一致，保留场景版本供对照；原工程编辑器内置模块不要擅自替换。
- 音频数据模块保留在原工程。本包列出依赖 ID/路径，未把 BGM 分片和发动机音频库复制成模型交付内容。角色服务中本来内嵌的音效仍随该脚本保留。
- 不包含账号凭证、AI 会话日志、整项目存档和无关赛道资源。资源 URI 是定位信息，并不等于 GitHub 中存在可运行的云游戏服务。

## 建议交接方式

美术先选一辆常规四轮车、赤巡摩托、两辆节日车各做样板；分别验证四轮/两轮/独立 Body 的接口后再批量。停车场分为主体、装饰、地标、NPC、舞台五组交付，保持同一世界尺度。模型、材质表、节点/挂点表、预览图和接口变更说明一并更新，随后由接入人员在原工程中替换验证。
